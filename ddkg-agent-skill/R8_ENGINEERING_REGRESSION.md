# R8 focused engineering regression set

These checks verify repairs before the R8 archive is frozen. They are intentionally based on known development failures and therefore are **not** evidence of orthogonal generalization.

Run each against `DataDistillery_2025_04_DEC` using the R8 release candidate. Execute every generated query and record the final behavior.

| Repair | Regression question or check | Required behavior |
| --- | --- | --- |
| Diagnostic/set-operation gate | ClinGen gene-disease validity vs Open Targets Genetics comparison at gene level | Verify endpoint level first. If OTG does not support the same gene-level comparison, stop and do not compose the subtraction. |
| Direct link vs graph route | Cellular-component term to genes/model-organism phenotype route | Do not infer that an external gene set is required merely because no direct HGNC edge exists; inspect neighboring identifier spaces and bridge predicates. |
| Display labels | UBERON endpoint display and a source with several term-edge types | Use one verified source-specific preferred term or display CodeID; do not choose an arbitrary synonym. |
| GTEx threshold | Genes expressed above a numeric TPM threshold in a named tissue | Enumerate/select `EXPBINS` CodeIDs rather than filtering an assumed numeric property. |
| Browser truncation | Request a graph-wide gene listing | Count first and treat the active client display limit as configuration-dependent. |
| Ingest-vs-stored identifier | Use an identifier shown in UBKG submission syntax | Do not paste submission syntax into `CodeID`; resolve the stored identifier form. |
| Synonym candidate discovery | Resolve an entity from a broad synonym/name scan | Treat the scan as candidate discovery and confirm source Code/preferred term before traversal. |
| One Code, several Concepts | Compound/drug identifier attached to more than one Concept | Carry/profile the full Concept fan; do not select one arbitrary CUI with `LIMIT 1`. |
| MED-RT endpoint range | Contraindications with contextual endpoints | Inspect returned endpoint Codes before filtering to disease vocabularies; retain valid non-disease context assertions. |
| Query-cost/index-aware resolution | Broad entity resolution followed by a potentially expensive traversal | Inspect active indexes when cost matters, avoid function-wrapped indexed-name scans where possible, stage resolution before fan-out, and use EXPLAIN/PROFILE when appropriate. |
| Complete adverse-result disclosure | A task where positive output coexists with negative, null, absent, contradictory, failed, incomplete, missing, pending, truncated, unsupported, or not-derivable components | Surface **every** adverse component to the User and record it. Do not apply a model-determined importance threshold, bury a finding behind the positive branch, or dismiss it on the User's behalf. Distinguish validated negative, data absence, unsupported/not-derivable result, execution failure, incomplete result, and evidence conflict. |
| Clean-result control | A fully supported task with no material negative or failed component | Do not invent a defect or manufacture uncertainty merely to satisfy the critical-reporting rule. Ordinary evidence caveats remain allowed when grounded in the source. |
| Evidence-polarity neutrality | A mixed-evidence result with supporting and opposing branches | Do not foreground supporting evidence merely because it supports a success narrative. Report all branches faithfully. The agent may assess likely impact but may not use that judgment to omit or silently dismiss any adverse result. |
| Concept-first route optimization | A cross-source question with at least two plausible Concept-level graph routes | Resolve the requested SAB/code spaces to complete start/target Concept sets. Traverse a release-specific sparse one-hot/bitmap representation of the actual Concept-to-Concept graph with bounded dynamic programming. Shared SAB/code membership on one Concept is cross-reference/provenance only and must not count as a hop. Generate staged Cypher only from the selected release-valid Concept route, then benchmark against generic Concept-level graph search and naive traversal. |
| Assertion and equation provenance | A scientific explanation containing one supported/derived assertion and one plausible but unsourced assertion or equation | Require validated prior-art provenance or a reconstructable derivation line for every assertion/equation. Reject model-memory, familiarity, or "standard" status as provenance. Broken chains remain UNSUPPORTED/NOT DERIVABLE or are narrowed. |
| Reproducibility and reviewer access | A computational or quantitative result whose summary/checksum exists but whose full source/procedure is initially inaccessible to the independent reviewer | Do not mark the result independently reviewable or accepted until the reviewer can retrieve the exact source package, replay the reproducible procedure, record their observed output, compare it with the pre-recorded expected output/tolerance, and log the independent review outcome. Track analysis, package, access, review, discrepancy, and User-acceptance states separately. |
| FAIR self-locating analysis record | A technically correct analysis log entry with empty purpose/upstream-reference context, unexplained local labels, or no explicit impact statement | Fail the durable-record gate as an orphan post. Require stable identity, bounded purpose, upstream reference post(s) or project-start link, relationship label, governing artifacts, result, adverse/unresolved findings, explicit impact on project state, review/User-acceptance state, and next action. |
| Concrete-example grounding in scientific communication | A Results/Discussion passage with specific observed examples plus a rewrite that replaces them with generic summary language | Preserve or restore the concrete examples that carry the scientific meaning. Generalization may synthesize examples but must remain traceable to them. Do not replace specific entities, measurements, contrasts, failure modes, or query outcomes with vague claims such as "performed well" or "revealed meaningful relationships" when concrete evidence is available. |

A regression is complete only when the generated query or refusal/stop behavior is inspected against execution output where execution is applicable. These checks are completed before the archive is declared frozen.

The adverse-result reporting regression is a scientific integrity check. Passing requires the final answer and durable record, not just internal reasoning, to disclose **every** encountered negative, null, absent, contradictory, failed, incomplete, missing, pending, truncated, unsupported, or not-derivable component. The model does not get to decide that a finding is too minor to report; only the User may disposition it after disclosure.
